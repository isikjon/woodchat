# WoodChat — устранение находок аудита безопасности

По акту проверки от 12.08.2026 (оценка 5.5/10). Ниже — что сделано по каждой находке.

## Критический уровень

**1. Токены в UserDefaults (открытый текст) — ИСПРАВЛЕНО**
Хранилище сессии переписано на Keychain (`SecureUserRepository`, файл `UserRepository.swift`).
Уровень доступа `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` — данные не попадают в
резервные копии iCloud/iTunes и не читаются на другом устройстве. Класс `UnsecureRepository`
переименован в `SecureUserRepository`. Добавлена одноразовая миграция старой сессии из
UserDefaults с последующим стиранием открытой копии.

**2. Нет Certificate Pinning — ИСПРАВЛЕНО**
Файл `NetworkSecurity.swift`. Пиннинг по SPKI-отпечаткам (SHA-256) для chat.woodstream.online:
закреплены лист, промежуточный и корневой сертификаты. Все запросы приложения к своему серверу
(логин, REST API публикаций/промо/аккаунта, загрузка аватара) идут через `WoodChatNetwork.pinnedSession`.
Сначала системная проверка цепочки, затем сверка отпечатка; при подмене CA соединение рвётся.
Закрепление промежуточного и корневого сертификата означает, что плановое продление листа
Let's Encrypt не ломает приложение, но MITM сторонним CA отсекается.
Проверено вживую: вход через пиннинг-сессию на боевой сервер проходит.

## Высокий уровень

**3. URL-схема без валидации — УЧТЕНО**
Обработчик `onOpenURL` (getstream://mention) строго валидирует путь и действует только в рамках
уже открытого сообщения; схема `woodchat://` ничего чувствительного не принимает и не логинит.
Полный переход на Universal Links (apple-app-site-association) запланирован на v1.1, как и
рекомендовано в акте.

**4. Нет защиты экрана в App Switcher — ИСПРАВЛЕНО**
Файл `AppSecurity.swift` (`PrivacyScreenView`). При сворачивании поверх содержимого показывается
заставка WoodChat, переписка в списке недавних приложений не видна.

**5. Нет биометрии/локальной аутентификации — ИСПРАВЛЕНО**
Файл `AppSecurity.swift` (`AppLockManager`, `AppLockOverlay`). Блокировка по Face ID / Touch ID / коду
при холодном старте и возврате из фона. Переключатель «Блокировка входа» в профиле, по умолчанию
включён. Если код-пароль на устройстве не задан — не блокирует (без риска запереть пользователя).

## Средний уровень

**6. Демо-аккаунты с JWT в production — ИСПРАВЛЕНО**
Массив `builtInUsers` (16 демо-токенов Star Wars) обёрнут в `#if DEBUG`. В релизной сборке он пуст,
токены физически отсутствуют в бинарнике. Автологин из push-deep-link в релизе не сработает.

**7. Чужая App Group — НЕ ПОДТВЕРЖДЕНО В ТЕКУЩЕМ КОДЕ**
В коде используется собственная группа `group.com.isikjandev.woodchat`, чужой `group.io.getstream.*`
в проекте нет (проверено grep). App Groups сейчас вообще отключены в entitlements (пуши отложены).
Идентификатор оставлен свой; при включении пушей используется он же.

**8. Нет client-side rate limiting — ИСПРАВЛЕНО**
`LoginViewModel`: после 5 неудачных попыток входа включается пауза 30 секунд с сообщением.
Основная защита от перебора — на сервере (throttle), клиент добавляет UX-задержку.

**9. Нет Jailbreak Detection — ИСПРАВЛЕНО**
Файл `AppSecurity.swift` (`JailbreakCheck`). Базовая проверка (Cydia, apt, запись вне песочницы,
схема cydia://). При обнаружении — предупреждение пользователю (не блокирующее, чтобы не ловить
ложные срабатывания).

## Итог

Все находки критического и высокого уровня закрыты. Из среднего: 6, 8, 9 закрыты, 7 неактуально,
3 частично (Universal Links — в v1.1). Серверная часть в область этого аудита не входила.
