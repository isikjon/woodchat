## 3. Важно: способ распространения

WoodChat обслуживает сотрудников и клиентов одной компании. В отклонении от 02.09.2026 Apple сослалась именно на **3.2 — Business**: выбран публичный App Store, хотя аудитория ограничена конкретным бизнесом. Одна только открытая регистрация или замена описания не устраняет это замечание.

Варианты:

**А. Unlisted App — установка по прямой ссылке (подходит для клиентов на личных устройствах).**
Приложение не показывается в поиске и подборках App Store. Установить его может любой обладатель ссылки, поэтому вход и серверные права доступа остаются обязательными. Готовую сборку нужно отправить на App Review, указать намерение использовать Unlisted в Review Notes и подать отдельный запрос Apple. До одобрения запроса в карточке оставляют Public Distribution. [Официальная инструкция Apple](https://developer.apple.com/support/unlisted-app-distribution/).

**Б. Private Distribution — для конкретных организаций.**
Приложение доступно указанным организациям через Apple Business или Apple School Manager. Это не обычная ссылка для всех клиентов и не «упрощённая проверка». После одобрения переход между Public и Private требует новой карточки приложения; исключение — перевод Public в Unlisted. [Способы распространения Apple](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/set-distribution-methods).

**В. Публичный App Store.**
Выбирать только если продукт действительно рассчитан на широкую публичную аудиторию и это можно показать ревьюеру. Не описывать внутренний чат как универсальную новостную платформу и не обещать отсутствующие функции.

TestFlight используйте для проверки сборки, а не как постоянный способ рабочего распространения.

## 4. Сборка архива (пошагово)

1. Открыть проект: `open StreamChatSwiftUI.xcodeproj`
2. В списке схем сверху выбрать **WoodChat**, устройство — **Any iOS Device (arm64)**.
3. Выбрать таргет **DemoAppSwiftUI** → вкладка **Signing & Capabilities** → в поле **Team** выбрать команду организации (не Personal Team).
4. Проверить **Bundle Identifier**: `com.isikjandev.woodchat` (или ваш, если занят).
5. Меню **Product → Archive**. Сборка займёт несколько минут.
6. В открывшемся окне Organizer нажать **Distribute App** → **TestFlight & App Store** → **Upload**.
7. Дальше — в App Store Connect: заполнить карточку (§5), добавить тестировщиков в TestFlight.

Проверить сборку из терминала можно так:

```bash
xcodebuild -scheme WoodChat -project StreamChatSwiftUI.xcodeproj -configuration Release -destination 'generic/platform=iOS' archive -archivePath ~/Desktop/WoodChat.xcarchive
```

## 8. Пуш-уведомления — ВКЛЮЧЕНЫ

Настроены 17.08.2026 по ключу APNs заказчика (Key ID 9A9WQKL28K, Team ID Q5CPN332XB).

**Что сделано:**
- Ключ `.p8` лежит только на сервере: `/var/www/wood/data/www/stream-gateway/secrets/` (права 600, в git не попадает).
- Настройки в `.env` шлюза: `APNS_KEY_PATH`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC`, `APNS_ENVIRONMENT`.
- Шлюз: эндпоинты `POST/GET/DELETE /devices` (регистрация устройства из SDK), отправка через APNs HTTP/2 с JWT ES256, автоотключение мёртвых токенов.
- Пуш уходит участникам беседы, которых нет онлайн (нет открытого WebSocket), кроме самого отправителя. Бейдж — суммарное число непрочитанного.
- Приложение: `aps-environment = development`, запрос разрешения при входе, регистрация токена через `addDevice(.apn)`.

**Проверено:** Apple принимает ключ и подпись (на выдуманный токен отвечает `BadDeviceToken`, а не отказом в авторизации); сквозной путь сообщение → пуш → очистка мёртвого токена отработал на проде.

**ВАЖНО при переходе на TestFlight/App Store:**
1. Проверить, что в подписанном архиве для распространения entitlement `aps-environment` имеет значение `production` и соответствует provisioning profile. Debug-сборкам по-прежнему нужна sandbox-среда.
2. Проверить маршрутизацию устройств и `APNS_ENVIRONMENT` в конфигурации шлюза: токены из TestFlight/App Store должны отправляться в production APNs. Изменения рабочего сервера согласовать отдельно.
Если этого не сделать — пуши на сборки из TestFlight приходить не будут (`BadDeviceToken`).

**Расширение уведомлений (App Groups)** пока не подключено — нужно только для показа картинок в пуше и точного бейджа в фоне. Текст, звук и переход в нужный чат работают без него.

## 10. Если Apple отклонит

Самые вероятные причины и что отвечать:

**«Приложение для конкретного бизнеса» (3.2)** → выбрать Unlisted или Private Distribution в соответствии с реальной аудиторией (§3). Не отвечать, что публичная регистрация сама по себе делает приложение массовым.

**«Метаданные не соответствуют приложению» (2.3)** → заменить текст «сверхбыстрая новостная платформа» на описание из §5, проверить название, подзаголовок и скриншоты. Указывать только функции, доступные в отправленной сборке. [Правила метаданных Apple](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata).

**«Нет удаления аккаунта» (5.1.1v)** → указать путь: значок профиля → «Профиль и аккаунт» → «Удалить аккаунт».

**«Нет механизма жалоб на контент» (1.2)** → в приложении есть блокировка пользователей и жалоба на сообщение (долгое нажатие на сообщение), жалобы уходят администратору.

**«Не работает демо-аккаунт»** → проверить, что учётная запись активна, и что сервер доступен снаружи.
